# Harvester 2.1 local update

The daily-use app is `~/Applications/Harvester.app`. The development app
`build/Harvester 2.app` uses a separate queue and should stay closed during normal use.

## New app controls

- **Preview** plays a completed silent video inside Harvester.
- **Send to Chromatron** sends the completed video through macOS file-open handling.
  Choose the current Chromatron app once; change it under **Options for new submissions**.
  macOS accepting the request is not a guarantee that the receiving app has loaded it.
  The owner’s Chromatron worker is implementing its incoming **Harvester queue**.
- **Options for new submissions** offers all-keyframe H.264 (default) or smaller
  H.264 with regular keyframes, plus WAV or lossless FLAC audio.
- Optional start/end times accept seconds or HH:MM:SS. The same range applies to
  video and audio. Blank means full source. Different ranges or presets become
  separate jobs; identical choices deduplicate, even if the name changes.
- Trimming happens after acquisition. Full-source 60-minute / 500 MB limits still
  apply; this is not a download-only-the-range feature.
- Download and encoding progress is per stream/stage, not a made-up total or ETA.
  Unknown download sizes have no percentage. Completed new jobs show output size.
  Options show free disk space and an approximate WAV budget; variable video size
  is deliberately not guessed.

## Firefox controls require the new extension

Source is in `extension/firefox`; the unsigned review package is
`dist/harvester-firefox-2.1.0.zip`. It adds optional naming, **Harvest now**,
**Add to queue**, clip times, and a smaller-video choice for supported YouTube
and Reddit pages. The current signed extension remains installed and can still
submit ordinary links to v2, but does not show these new controls.

For a temporary test: visit `about:debugging#/runtime/this-firefox`, choose
**Load Temporary Add-on…**, and select the new ZIP or `extension/firefox/manifest.json`.
This temporarily replaces the same-ID installed add-on; restarting Firefox restores
the signed version. Do not do this while a legacy extension harvest is running.
A permanent update requires Mozilla signing. Do not disable Firefox signature checks.

**Add to queue** does not start an idle runner. An already running queue picks it
up automatically. **Harvest now** starts eligible work. Firefox status says that
the item was handed off; the app owns actual processing progress.

## Verification

124 Python tests pass, including real trimmed H.264/FLAC processing, matched video
and audio durations, invalid-range rejection, variant deduplication, safe numeric
progress, and native submission validation. `node tests/test_popup.cjs` exercises
the real popup's naming, queue-only, and immediate-start messages. Mozilla lint
reports no errors, warnings, or notices. Native preview playback was checked with
the two-second synthetic clip. The app's queue-refresh lifecycle uses a timer so
sheet presentation does not leave the job list stale.

Chromatron handoff is now verified end-to-end by its worker: the fixture appears
in its Harvester queue both while already running and after Harvester launches
it from a fully closed state. The receiver needed an NSApplicationDelegate
file-open handler. Target: /Users/scott/Documents/Chromatron/native-app/dist/Chromatron.app.
Incoming clips wait in that queue for the user to open.
